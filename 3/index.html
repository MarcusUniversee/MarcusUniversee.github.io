Part A.2: Recover Homographies

In this section, we use linear algebra to compute homographies from correspondences. This is done by solving the equation p2 = H p1, where p1 and p2 are correspondences from the first and second image. H is the 3x3 matrix with 8 unknowns, with the 9th value just for scale. This value can stay at 1. To make the equation work, we express the correspondences as (x, y, 1). Examples are shown for the East Asian Library pictures.

Below are three sets of correspondences on the image. Six correspondences were made for each image pair. This was determined experimentally to be number where adding more correspondences contributed to only marginal improvements.

To create the system of equations we can express this in terms of the correspondence points and the unknowns

Starting with the equation H p1 = p2

$$ \begin{bmatrix} a & b & c \\ d & e & f \\ h & i & 1 \end{bmatrix} \begin{bmatrix} x_1 \\ y_1 \\ 1 \end{bmatrix} = \begin{bmatrix} x_2 \\ y_2 \\ 1 \end{bmatrix} $$

This can be arranged into a system of equations

$$ a x_1 + b y_1 + c = x_2 \\ d x_1 + e y_1 + f = y_2 \\ h x_1 + i y_1 + 1 = 1 $$

Which can be simplifed to a system of two equations

$$ a x_1 + b y_1 + c - h x_1 x_2 - i y_1 x_2 = x_2 \\ d x_1 + e y_1 + f - h x_1 y_2 - i y_1 y_2 = y_2 $$

These two equations can now be solved using least squares!

Part A.3: Warp the Images

In this section, we warp the images in two ways: Nearest Neighbor and Bilinear Interpolation using the homography matrix. In nearest neighbors, a warped point is rounded to the nearest integer. In bilinear interpolation, a warped subpixel is a combination of surrounding pixels, weighted based on the fractional difference between the point and its surroundings. Note that for the warped images, we increase the canvas size. This will be important for the next part where we blend images together. Below are two examples of warping

Part A.4: Blend the Images into a Mosaic

In this section, we blend our warped images together to create a composite image. I use the following procedure to blend images together.

  1. Align images onto the same canvas. This is actually done in the previous part, which is why the canvas increased. For the middle image, the edges are padded equally such that it ends in the same canvas dimensions.
  2. Create masks in overlapping regions. For horizontal images, we take the left and right edges of an overlapping region and apply a linear horizontal alpha blend/feathering. For example, on left edge of an overlapping region left image alpha = 1 and right image alpha = 0. This goes the same for vertical images, except we apply a linear vertical alpha blend/feathering.
  3. Perform distance weighting in overlapping regions. Even after the masks, edge artifacts still appear at the edges. For horizontal, this would be at the top/bottom edge of an image which ends in the overlapping section. Since the image is warped, we cannot just apply smoothing in a line easily. Therefore, we perform distance weighting based on its closest distance to an edge (missing pixel) in the overlapping region. This blends the edges of images in overlapping regions for the opposite axis (top/bottom edge in horizontal blend). Again, the same goes for vertical.
  4. Recombine the images weighted by their alpha value. All pixels that are combined with empty parts of the other images are set to full value (alpha = 255).

Part B: Feature Matching for Autostitching

Note: The process is only shown for one example image(s), but the same exact process is done to create 3 automatic mosaics, which is shown at the end.

Part B.1: Harris Corner Detection

In this section, we use harris corner detection to find corner features in an image. We then apply Adaptive Non-Maximal Suppression (ANMS) to reduce the maximum number of features (due to computation cost), while still achieving a good distribution over the whole image.

First, lets look at the results of the harris detector we are given to gain some intuition. Starting with the h matrix

This matrix shows us the strongest corners, which are mostly in the book section. However, we want values to be spread out. So, we can instead show the peak local maxes across the whole image, where each peak is separated by some minimum distance (d). This part is also given in the harris detector, so we can draw a circle at every coordinate.

Next, we apply Adaptive Non-Maximal Suppression (ANMS) to reduce the maximum number of features (due to computation cost), while still achieving a good distribution over the whole image. We can follow minimum suppresion radius equation in the paper, which finds the minimum distance for each point to any other point such that its h value (corner strength) is less than 0.9 * the h value of the other point. Then, the top n (500) are taken.

Due to the large resolution of the images, we need to reduce the number of interest points before making the minimum distance matrix calculations (or it results in a matrix that takes over 12 gb in memory), so we adjust the minimum distance (d) in the harris detector.

$$r_i = \min_j |x_i - x_j|, s.t. f(x_i) < c_{robust} f(x_j), x_j \in \mathcal{I}$$

However, after not being completely satisfied with these images (several points on flat surfaces and some corners missing), I tried another approach, keeping d to a lower value, but filtering out "very weak" (> 0.1 threshold) h values corner strengths. This has the effect of slightly reducing the uniformity (some points are very pretty together) of the interest points across the image for more accurate corner detection and less edge detection.

Part B.2: Feature Descriptor Extraction

In this section, we create 8x8 feature descriptors, which are blurred sampled patches around the interest points created from the previous part. To create these descriptors (as described in the paper), we do the following:

  1. Blur the entire image such that spacings (frequencies) are approximately 5 pixels. This is to prevent aliasing.
  2. For each point, take a 40x40 patch and downsample to 8x8. Due to the previous blur, this makes the sampling rate approximately once per pixel.
  3. Normalize to mean 0 and standard deviation of 1.

These feature descriptors are now standardized, normalized, and free of high detail, capturing the overall pixel magnitudes from that corner. Part B.3: Feature Matching

In this section we take the feature descriptors made and match them across images. Here are the steps discussed in the paper:

  1. Compute the L2 distance for every combination/pair between both images
  2. Take the nearest neighbot (minimum) and second nearest neighbor (second minimum) L2 distances for each feature in the first image, and compute the error ratio: 1-NN/2-NN
  3. Only keep the first image feature descriptors that have an error ratio below some threshold (Lowe's).
  4. For every first image feature descriptor that still exists, take its corresponding nearest neighbor feature descriptor for the second image (which is already computed from step 2), and this is a match!

From the paper, we choose a threshold of 0.6. Below are a couple examples of feature descriptor matches:

Part B.4: RANSAC for Robust Homography

In this section, we use RANSAC, or RAndom SAmple Consensus, to remove outliers. This is done by computing homographies to warp points from one image to the other, and then comparing the warped point to its corresponding feature match. We follow the procedure from lecture:

  1. Randomly select four feature pairs.
  2. Compute a homography with these four pairs.
  3. Compute inliers, which are points such that the L2 distance between itself (warped by homography) and its feature match is below some error threshold.
  4. Repeat steps 1-3 for some amount of iterations, keeping the largest set of inliers.
  5. Compute a homography with the inliers.

We use this method to not only exclude outliers, but also to obtain an automatic homography matrix that is robust to outliers. Below, we choose the number of iterations to be 20 and the error threshold to be 3. Red are outliers, while green are inliers. Note that due to the random nature of this algorithm, there are some outliers that should be inliers, but there are enough inliers between the two such that the homography is robust. This could be improved with a larger number of iterations and error threshold tweaking.

Taking our homographies created from RANSAC, we use the same warping and blending method from Part A and create mosaics! Below are the mosaics, with the manual on the left side for comparison, and the automatic one on the right side

Overall, it seems looks like the automatic mosaic is a little bit worse than manual, but this makes sense, as us humans can use our past knowledge and understanding of the scene to find better correspondences. However, the automatic takes a lot less work!
