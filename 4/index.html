Part 1: Fit a Neural Field to a 2D Image

In this section, we fit a neural field to two images. I used the same MLP neural network from the spec (architecture shown below). This neural network has four linear layers of width 256, 256, 256, and 3. Each layer is followed by a RELU activation function except for the fourth layer, which is followed by a Sigmoid activation function to constrain output from 0 to 1. Before our inputs are passed into a model, we positionally encode the points at a max frequency of L = 10, leading to 2 (original x, y) + 10 * 2 (sin and cosine) * 2 (x, y). I used the positional encoding equation given in the spec. The overall input is pixel coordinates to RGB.

Here are the training results on the given test image and my own image at steps: 0, 50, 120, 200, 500, final (3000), and then the original image

I then vary the parameters width and L, setting width to 64 (so the linear layers are width 64, 64, 64, 3) and L to 4. Here are the results for all four combinations. These results are very interesting! It seems that decreasing max frequency (L) makes the image more smooth and less detailed, while decreasing width adds noise to the image.

Part 2: Fit a Neural Radiance Field from Multi-view Images

Part 2.1 and 2.2: Utility functions for rendering

In this section, we create some utility functions to convert a 2d pixel on a camera to a ray. The ray can then be projected into the 3D space via sampling, allowing for the volumetric rendering. This is done with the following steps/functions

  1. Camera to world conversion: Using the c2w matrix, transforms a point from camera to world This is simply done with matrix multiplication.
  2. Pixel to camera conversion: Using the instrinsic matrix, transforms a point from pixel coords (u,v) to camera coords (x_c, y_c, z_c). Since the dimension is effectively increasing, we define a parameter s which represents the depth of the point along the optical axis. For training, we set this to 1.
  3. Pixel to ray: Using the previous to functions, we convert a pixel to its world coordinates. The ray origin is the translation component of the camera to world matrix, while the direction is given by the normalized difference between the pixel's world coordinates and the ray origin, (which is the same as the camera origin).
  4. Sampling rays: To sample rays, I create a torch Dataset and use torch's Dataloader class to sample rays. To populate the initial rays data, I get a 2d array of all the pixel points based on my image width/height. Then, I call the pixel to ray function on every camera to world matrix and store these as a torch tensor. Then, in the Dataset's __getitem__(self, id) function, I simply return the populated ray and image tensors indexed by the id.
  5. Sampling along rays: For each ray, we sample N points along the ray between near and far bounds. I use stratified sampling to randomly sample points within evenly spaced intervals along the ray. However, this should only be used during training; for validation/test, we use uniform sampling. For the rest of the project, I set N to 64.

Part 2.4: Neural Radiance Field

Next, we implement the MLP for the Nerf. The architecture is shown in the image below. This is straight from the spec, and we use the same parameters for width. For positional encoding of the inputs, we use L=4. Overall, the input is a 3D point (x, y, z) and a 2D viewing direction (theta, phi), and the output is the RGB color and density at that point. In this implementation, the 3D inputs are injected at the beginning and middle to ensure that the model does not forget inputs. The view direction is only added for the RGB output since it has no effect on density.

Part 2.5: Volume Rendering and Training a Nerf

Next, we need a way to render the output of the Nerf MLP into an image. This is done with volume rendering. For each pixel, we acculumate the colors of sample points along the ray, scaled by their own alpha (opacity) values, which are computed from density, as well as the running product of (1 - alpha) values of all previous points along the ray. This gives us the final color of the pixel, accounting for occlusions and transparency. The equations for this process are given in the spec.

We then train the Nerf MLP on the lego dataset. This is done using an Adam optimizer with a learning rate of 5e-4 and a batch size of 10000 rays. We run this for 5000 iterations and achieve the following results.

Part 2.6: Training with your own data

In this section, we use the same method to train on our own captured dataset. One difference from the previous section is that the image resolution is significantly higher (over 10x), so I downscale the images when creating the dataset to save gpu memory and training time. Due to this, the focal lengths in the intrinsic matrix must also be downscaled by the same factor. For my data, I downscaled by 2x for training, and downscaled another 4x only when rendering images to png. Another difference is that I trained for 10000 iterations, double the previous section.
